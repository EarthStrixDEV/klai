# Module: ร้านโปรด (Favorites)

*(ใหม่ใน v0.8)*

## หน้าที่
หน้าแยกในเมนูหลัก แสดงรายชื่อร้าน/ปั๊มที่ user กดบันทึกไว้จากหน้า Map หรือ List Store — ไม่มี login/account ทุกอย่างอยู่ใน `localStorage` ของเบราว์เซอร์นั้นๆ ใช้ card component เดียวกับหน้า List Store ต่างกันแค่แหล่งข้อมูล

## ทำไมถึงอยู่ใน Klai
Klai ถูกใช้ซ้ำๆ กับร้าน/ปั๊มเดิมๆ ที่ user แวะบ่อย (ปั๊มประจำ, ร้านสะดวกซื้อใกล้บ้าน/ที่ทำงาน) — การต้องยิง Overpass query + กรองแบรนด์ + scroll หาใหม่ทุกครั้งทั้งที่จริงๆ อยากไปร้านเดิมเป็นแรงเสียดทานที่ไม่จำเป็น การบันทึกร้านโปรดช่วยให้เข้าถึงร้านที่ใช้บ่อยได้เร็วโดยไม่ต้องเพิ่มต้นทุน infrastructure เลย (เก็บแค่ฝั่ง client)

## Flow การทำงาน (ทีละขั้น)

1. **บันทึกร้าน** — จากหน้า Map (bottom sheet/popup) หรือ List Store (การ์ด) กดไอคอนดาว → เขียน object `{id, name, brand, lat, lng}` เพิ่มเข้า array ใน `localStorage` (key เช่น `klai_favorites`)
2. **เปิดหน้า Favorites** — อ่าน array จาก `localStorage` ถ้าว่างเปล่า แสดง empty state (ดูด้านล่าง)
3. **ขอตำแหน่งปัจจุบัน** (เหมือนหน้า Map/List Store) เพื่อคำนวณระยะทางใหม่จากจุดที่ user ยืนอยู่ตอนนี้ — **ไม่ใช้ระยะทางที่คำนวณไว้ตอนบันทึก** เพราะ user อาจเปิดหน้านี้จากคนละที่
4. **Re-verify พิกัด (แนะนำ)** — ยิง Overpass query ตาม `id` ที่บันทึกไว้เพื่อเช็คว่าร้านยังอยู่จริง/พิกัดไม่เปลี่ยน แทนที่จะเชื่อ `lat/lng` เก่าเฉยๆ (ร้านอาจย้าย/ปิดไปแล้วตั้งแต่บันทึก) — ถ้า query ไม่เจอ node เดิมอีกต่อไป ให้ขึ้น tag เตือน "ร้านนี้อาจไม่มีอยู่แล้ว" บนการ์ดแทนที่จะลบออกอัตโนมัติ (ให้ user เป็นคนตัดสินใจลบเอง)
5. **Render การ์ด** — ใช้ component เดียวกับ List Store เรียงตามระยะทางใหม่ที่คำนวณได้
6. **กดดาวอีกครั้งเพื่อลบ** — toggle เดิม กดซ้ำที่การ์ดในหน้า Favorites (หรือจากหน้า Map/List Store) เพื่อลบออกจาก `localStorage`

## โครงสร้างหน้า
- Top bar: ปุ่มย้อนกลับ + หัวข้อ "ร้านโปรด" + จำนวนร้านที่บันทึกไว้
- รายการการ์ด (component เดียวกับ List Store: badge แบรนด์, badge ระยะทาง, ปุ่มนำทาง, ปุ่มลบ/ดาว)
- Empty state: ไอคอน + ข้อความชวนบันทึก เช่น "ยังไม่มีร้านโปรด กดไอคอนดาวจากหน้าแผนที่หรือรายชื่อร้านเพื่อบันทึกไว้ที่นี่" พร้อมปุ่มลัดไปหน้า Map

## กลไกทางเทคนิค
- **Storage**: `localStorage` array ของ `{id, name, brand, lat, lng}` — ไม่ผูกกับ account, ไม่ sync ข้ามอุปกรณ์/เบราว์เซอร์ (ข้อจำกัดที่ต้องสื่อสารกับ user ถ้าจำเป็น เช่น ถ้าสลับเครื่อง/ล้าง browser data ร้านโปรดหายหมด)
- **ไม่มี backend/DB กลาง** — สอดคล้องกับสถาปัตยกรรม "0 maintenance" ของ Klai ทั้งโปรเจกต์
- **Data staleness** — พิกัด/ชื่อร้านที่บันทึกไว้เป็น snapshot ตอนกดดาว อาจไม่ตรงกับ OSM ปัจจุบันแล้วถ้าร้านย้าย/เปลี่ยนชื่อ/ปิดกิจการ ควร re-verify ทุกครั้งที่เปิดหน้านี้ตามข้อ 4 ด้านบน ไม่ใช่แสดงข้อมูลเก่าตรงๆ
- **ไอคอนดาว (star toggle) เป็น shared component** ใช้ร่วมกันทั้งหน้า Map, List Store และ Favorites เอง — state เดียวกัน อัปเดตพร้อมกันทุกหน้าโดยไม่ต้อง refresh

## หมายเหตุทางเทคนิค
- ไม่จำเป็นต้องมี limit จำนวนร้านโปรดสำหรับ MVP (localStorage เก็บได้หลาย MB ข้อมูลแค่นี้เล็กมาก) แต่ถ้าจะทำ P1 อาจใส่ limit ป้องกัน list ยาวเกินไป (เช่น 50 ร้าน)
- ปุ่ม "ดูบนแผนที่" (floating action เหมือนหน้า List Store) ควรมีในหน้านี้ด้วย — สลับไปหน้า Map พร้อม pin เฉพาะร้านโปรดเท่านั้น (ไม่ใช่ผลค้นหาทั่วไป)
